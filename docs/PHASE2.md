# Phase 2 - Ollama Provider

Status: **implemented on `feature/v0.1-mvp`; pending local Windows acceptance**

## Goal

Replace the Phase 1 simulator with a real local Ollama model while preserving the Thread / Turn protocol.

Default provider:

```text
Ollama
http://127.0.0.1:11434
```

Preferred model:

```text
qwen3-coder:30b
```

Default context window:

```text
32768 tokens
```

The context is intentionally conservative for initial 32 GB VRAM validation. It can be overridden with:

```powershell
$env:LCA_OLLAMA_NUM_CTX = "65536"
```

before starting the Desktop.

## Provider architecture

```text
Agent Server
   |
   +-- OllamaProvider
         |
         +-- GET  /api/tags
         +-- POST /api/chat (stream=true)
```

The provider implementation is isolated under:

```text
agent/llm/
  base.py
  ollama.py
```

Future online or OpenAI-compatible providers can be added without changing the Desktop protocol.

## Implemented behavior

- Detect Ollama availability.
- List locally installed models.
- Prefer `qwen3-coder:30b` when installed.
- Select a model per Thread.
- Stream real model output through `turn.delta`.
- Keep successful user/assistant exchanges in Thread memory.
- Reload current in-memory Thread history.
- Cancel a running Ollama request with Stop.
- Report provider errors as `turn.failed`.
- Show provider online/offline state in Desktop.
- Show model dropdown in Desktop.
- Show configured context window.

## Safety boundary

Phase 2 is still chat-only.

The system prompt explicitly tells the model that it does not yet have:

- filesystem tools
- shell tools
- Git tools
- local execution tools

The model must not claim it inspected, changed, executed, tested, or verified local files.

Those capabilities begin in Phase 3.

## Environment variables

Optional overrides:

```powershell
$env:LCA_OLLAMA_URL = "http://127.0.0.1:11434"
$env:LCA_OLLAMA_MODEL = "qwen3-coder:30b"
$env:LCA_OLLAMA_NUM_CTX = "32768"
$env:LCA_OLLAMA_TEMPERATURE = "0.2"
```

## CI strategy

CI does not require a real Ollama installation or GPU.

The test suite starts a local fake Ollama API and validates:

- model listing
- default-model selection
- streaming NDJSON chat
- context-window request option
- final token counters

This keeps CI deterministic while local Windows acceptance verifies the real GPU model.

## Windows acceptance

Update:

```powershell
git checkout feature/v0.1-mvp
git pull origin feature/v0.1-mvp

.\scripts\dev\bootstrap.ps1
.\scripts\dev\start.ps1
```

Verify in the Desktop:

1. Bottom-left status shows `phase2`.
2. Top-right shows **Ollama Online**.
3. Model dropdown contains `qwen3-coder:30b`.
4. Create a new Thread.
5. Send:

```text
用中文简单介绍一下你自己，并告诉我你现在能不能直接读取我的本地代码。
```

Expected behavior:

- Response is generated by the real local model.
- Text streams progressively.
- It should state that it cannot yet directly read local code.
- Model selector displays `qwen3-coder:30b`.

Then send a longer coding question and press **Stop** during generation.

Expected:

- Generation stops.
- UI displays `Turn cancelled.`
- App remains usable.

## GPU verification

While the model is generating, run in another PowerShell:

```powershell
ollama ps
nvidia-smi
```

Use these results to decide whether Phase 3 should stay at 32K context or increase to 64K.

## Exit criteria

Phase 2 is accepted when:

- Windows and Ubuntu CI pass.
- Ollama Online is shown locally.
- `qwen3-coder:30b` is selectable.
- Real local generation streams successfully.
- Thread context works for at least two turns.
- Stop cancels real generation.
- No system Python is used.
- Local GPU usage is confirmed.

After acceptance proceed to **Phase 3: Tool System v1**.
