# v0.3 Phase 23 — MCP Safety + Settings 人工验收

> 分支：`feature/v0.3`
>
> 自动化已覆盖：MCP stdio / Streamable HTTP、CRUD、SQLite schema 3、配置重启恢复、ToolAnnotations、本地风险分类、Read Only / Workspace 权限、Approval、secret 不进入 SQLite、Diagnostics 脱敏。
>
> 本页只验证 Windows Desktop 的真实 Settings、safeStorage 与 Agent 调用体验。

## 1. 启动

Windows PowerShell：

```powershell
git checkout feature/v0.3
git pull
.\scripts\dev\start.ps1
```

打开一个普通测试项目。

## 2. 添加本地 stdio MCP Server

打开：

```text
Settings -> MCP
```

点击：

```text
New server
```

填写：

```text
Name:
phase23-test

Transport:
stdio

Command:
python

Arguments · one per line:
tests\fixtures\mcp_test_server.py

Enabled:
On

Trusted server:
On

Timeout:
30
```

如果你的 `python` 不在 PATH，可把 Command 改成当前仓库的：

```text
<仓库目录>\.venv\Scripts\python.exe
```

然后点击：

```text
Add server
```

预期：

- server 状态变为 connected；
- 显示 2 tools；
- `echo` 为 read-only；
- `large_text` 为 read-only；
- Refresh 可正常重新连接。

## 3. 验证 Read Only + trusted read-only

切到：

```text
Settings -> Safety -> Read Only
```

然后在聊天中输入：

```text
Use the MCP phase23-test echo tool to echo: hello phase23
```

预期：

- Agent 可以调用 MCP echo；
- Tool Card 顶部显示类似 `MCP · phase23-test`；
- 不应出现写权限 Approval；
- 返回内容包含 `hello phase23`。

## 4. 验证 untrusted MCP 不能绕过权限

回到：

```text
Settings -> MCP -> phase23-test
```

关闭：

```text
Trusted server
```

保存。

保持 Read Only，再请求使用 MCP echo。

预期：

- 该 MCP Tool 不再作为 Read Only Tool 暴露；
- 不会静默执行。

然后切到：

```text
Workspace
```

再次明确请求使用 MCP echo。

预期：

- MCP Tool 可以被模型发现；
- 执行前出现 Approval；
- Allow once 后才执行。

这一步用于确认“server 声明自己只读”不能绕过本地信任策略。

## 5. 验证 MCP secret 安全存储

在该 server 中设置：

```text
Secret environment keys:
TOKEN

Secret environment values · JSON:
{"TOKEN":"PHASE23_SECRET_DO_NOT_LEAK"}
```

保存。

预期：

- Settings 显示 credential 已配置；
- 不显示 secret 明文。

关闭应用并重新启动：

```powershell
.\scripts\dev\start.ps1
```

再次打开 Settings -> MCP。

预期：

- server 配置仍存在；
- secret 仍显示 configured；
- secret 输入框不回显原值。

如果 Windows 当前环境支持 Electron safeStorage，应显示 OS-protected storage；如果系统不可用，则产品设计为 session-only，不允许明文回退到 SQLite。

## 6. 验证 Diagnostics 脱敏

打开：

```text
Diagnostics
```

预期新增 MCP 卡片，至少显示：

- Servers
- Enabled
- Connected
- Tools

点击：

```text
Copy report
```

粘贴到记事本，搜索：

```text
PHASE23_SECRET_DO_NOT_LEAK
```

必须：

```text
0 occurrences
```

Diagnostics 可以显示 MCP server 名称、transport、connected、tool count，但不能包含凭据明文。

## 7. 清理测试 Server

回到：

```text
Settings -> MCP -> phase23-test
```

点击：

```text
Delete server
```

预期：

- server 从列表消失；
- 对应 MCP tools 从 Agent 可用工具中消失；
- protected secret 一并删除。

## 验收标准

以下全部正常即可认为 Phase 23 通过：

1. MCP Settings CRUD 正常；
2. stdio fixture 能连接并发现 2 个 tools；
3. trusted read-only 在 Read Only 模式可调用；
4. untrusted MCP 在 Read Only 模式不可静默执行；
5. Workspace 下 untrusted MCP 必须 Approval；
6. MCP Tool Card 显示来源 server；
7. secret 重启后仍安全配置且不回显；
8. Diagnostics 不包含 secret；
9. 删除 server 后工具和 secret 都清理。
