# v0.3 Phase 24 — Repository Map + Explicit Context 验收

> 分支：`feature/v0.3`
>
> 本阶段人工验收统一使用固定工程：
>
> ```text
> manual-fixtures/phase24-context-demo
> ```
>
> 不再使用任意真实项目作为 Phase 24 验收基准。

## 1. 更新代码

```powershell
git checkout feature/v0.3
git pull
```

## 2. 准备固定测试工程

在仓库根目录执行：

```powershell
.\manual-fixtures\phase24-context-demo\setup_ignored_dirs.ps1
```

它会在固定测试工程里创建以下本地目录：

```text
node_modules
build
.venv
target
.gradle
```

这些目录故意放置可识别源文件，用于验证 Repository Map 是否正确忽略它们。

## 3. 启动 Local Coding Agent

```powershell
.\scripts\dev\start.ps1
```

在 Local Coding Agent 中选择 **Open project**，打开这个目录本身：

```text
<local-coding-agent仓库>\manual-fixtures\phase24-context-demo
```

不要打开整个 `local-coding-agent` 仓库。

## 4. Repository Map 固定预期

打开：

```text
Context
```

首次构建后，固定工程应包含这些可索引文件：

```text
README.md
pyproject.toml
package.json
src/app.py
src/version_info.py
src/service.ts
native/engine.cpp
java/Main.java
kotlin/App.kt
tests/test_app.py
```

预期：

```text
Indexed files = 10
```

语言统计应至少看到：

```text
python      3
typescript  1
cpp         1
java        1
kotlin      1
```

以下文件绝对不能出现在 Repository Map：

```text
node_modules/ignored.js
build/ignored.cpp
.venv/ignored.py
target/ignored.java
.gradle/ignored.kt
```

如果这些 ignored 文件出现，Phase 24 不通过。

## 5. 验证每行 Pin 按钮

在 Repository Map 找到：

```text
src/version_info.py
```

这一行右侧应有真正独立的：

```text
Pin
```

按钮。

点击后：

- 文件进入上方 `Pinned files`；
- 状态显示绿色 `Ready`；
- Repository Map 这一行按钮变成 `Pinned`。

## 6. 验证 Pinned Context

`src/version_info.py` 内容固定为：

```python
DEMO_APP_VERSION = "24.1"
DEMO_PROTOCOL = "context-demo"
```

Pin 后发送：

```text
只根据我当前显式提供的上下文，告诉我 DEMO_APP_VERSION 和 DEMO_PROTOCOL。
```

正确答案必须包含：

```text
DEMO_APP_VERSION = 24.1
DEMO_PROTOCOL = context-demo
```

重点验证：该文件已经作为 pinned context 进入 Turn。

## 7. 验证 Thread 隔离

保持 `src/version_info.py` 已 Pin。

新建一个 Thread。

打开 Context。

预期：

```text
Pinned files = empty
```

切回原 Thread。

预期：

```text
src/version_info.py
Ready
```

仍然存在。

## 8. 验证跨重启持久化

保持原 Thread 的 Pin 不删除。

关闭 Local Coding Agent，然后重新运行：

```powershell
.\scripts\dev\start.ps1
```

重新打开固定工程和原 Thread。

预期：

```text
src/version_info.py
Ready
```

仍然存在。

## 9. 验证 @file 临时上下文

先 Remove `src/version_info.py`。

发送：

```text
根据 @src/version_info.py 告诉我 DEMO_APP_VERSION 和 DEMO_PROTOCOL。
```

正确答案仍然必须包含：

```text
24.1
context-demo
```

然后打开 Context。

预期：

```text
Pinned files
```

仍然为空。

说明 `@file` 只影响当前 Turn，没有自动永久 Pin。

## 10. 验证普通非索引文件也可显式 Pin

固定工程还包含：

```text
notes/context_note.txt
```

它不会出现在 Repository Map 文件列表，因为它不是源码/配置索引目标。

在上方手工路径输入框输入：

```text
notes/context_note.txt
```

点击：

```text
Pin file
```

预期进入 Pinned files 并显示：

```text
Ready
```

发送：

```text
只根据 pinned context，告诉我 PHASE24_CONTEXT_NOTE 的值。
```

正确值：

```text
explicit-context-ready
```

这一步验证 Pin Context 不依赖 Repository Map 索引资格。

## 11. 验证缺失文件降级

Pin：

```text
notes/context_note.txt
```

然后在另一个 PowerShell 窗口执行：

```powershell
Rename-Item .\manual-fixtures\phase24-context-demo\notes\context_note.txt context_note.tmp
```

回到 Local Coding Agent，重新打开 Context。

预期该 Pin 显示：

```text
missing
```

但 APP 和 Thread 仍能正常使用。

恢复：

```powershell
Rename-Item .\manual-fixtures\phase24-context-demo\notes\context_note.tmp context_note.txt
```

## 12. 验证 Repo Map Refresh

记录当前：

```text
Revision
```

在固定工程根目录创建：

```powershell
Set-Content .\manual-fixtures\phase24-context-demo\src\phase24_added.py 'def phase24_added(): return "ok"'
```

点击：

```text
Refresh repo map
```

预期：

- Revision 增加；
- Repository Map 出现 `src/phase24_added.py`；
- Indexed files 从 10 变成 11。

测试结束删除：

```powershell
Remove-Item .\manual-fixtures\phase24-context-demo\src\phase24_added.py
```

再 Refresh，预期恢复：

```text
Indexed files = 10
```

## Phase 24 人工验收标准

以下全部满足即通过：

1. 固定工程 Indexed files = 10；
2. Python / TypeScript / C++ / Java / Kotlin 都被识别；
3. node_modules/build/.venv/target/.gradle 的故意文件均未进入 Repo Map；
4. Repository Map 每行有明确 Pin 按钮；
5. Pin 后进入 Pinned files 并显示 Ready；
6. Pin 是 Thread 独立的；
7. Pin 跨 APP 重启持久化；
8. `@src/version_info.py` 当前 Turn 可用但不会永久 Pin；
9. 非 Repository Map 文件 `notes/context_note.txt` 仍可手工 Pin；
10. Pin 文件消失时显示 missing，不导致 APP/Thread 失败；
11. Refresh 后新增源文件进入 Repo Map，删除后恢复固定基线。
