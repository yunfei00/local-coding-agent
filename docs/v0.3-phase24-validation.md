# v0.3 Phase 24 — Repository Map + Explicit Context 验收

> 分支：`feature/v0.3`
>
> 自动化已覆盖：Repository Map、多语言符号、ignored build/dependency trees、索引上限、增量刷新、schema 4、Pinned Context 持久化、缺失文件降级、`@file` 提取、ContextBudget 优先级与协议 CRUD。

## 1. 更新并启动

```powershell
git checkout feature/v0.3
git pull
.\scripts\dev\start.ps1
```

打开一个已有代码项目和 Thread。

## 2. 验证 Context 面板

顶部应出现：

```text
Context
```

点击后应看到：

- Indexed files
- Symbols
- Revision
- Bounded
- 语言统计
- Pinned files
- Repository map 文件列表

Repository Map 不应列出：

```text
.git
.venv
node_modules
dist
build
target
.gradle
.next
coverage
```

## 3. Pin 文件

在 Repository Map 列表中选择一个普通源文件，例如：

```text
README.md
agent/server/main.py
desktop/src/App.tsx
```

点击 `Pin`。

预期：

- 文件出现在 Pinned files；
- 状态为 `ready`；
- 切换到其他 Thread 后，该 Thread 有自己的独立 Pin；
- 切回原 Thread，Pin 仍然存在；
- 重启应用后 Pin 仍然存在。

## 4. 验证 pinned context 真正进入模型

建议 Pin：

```text
agent/core/version.py
```

然后问：

```text
只根据我当前显式提供的上下文，告诉我 APP_VERSION 和 PROTOCOL_VERSION。
```

预期模型能直接回答文件里的值，不需要先调用 read_file。

如果 Provider 自己仍决定调用 read_file，不视为失败；重点是 Context 使用事件中 pinned context 已进入固定上下文。

## 5. 验证 @file 当前轮上下文

先不要 Pin `agent/core/version.py`，或者把它 Remove。

发送：

```text
根据 @agent/core/version.py 告诉我 APP_VERSION 和 PROTOCOL_VERSION。
```

预期：

- 当前 Turn 自动读取该文件作为 `mentioned_file`；
- 不需要先在 Context 面板永久 Pin；
- 下一轮若不再写 `@agent/core/version.py`，它不会变成永久 Pin。

Composer 下方现在也会提示：

```text
@file adds one-turn context
```

## 6. 验证 Remove

在 Context 面板里对任意 Pin 点击：

```text
Remove
```

预期该文件立即从 Pinned files 消失，后续 Turn 不再作为 pinned context 注入。

## 7. 验证 Repo Map 手动刷新

记录当前：

```text
Revision
```

在项目里新增一个小源文件，例如：

```text
phase24_test.py
```

内容：

```python
def phase24_marker():
    return "ok"
```

点击：

```text
Refresh repo map
```

预期：

- Revision 增加；
- `phase24_test.py` 出现在 Repository Map。

测试后可以删除该文件，再 Refresh 一次。

## 8. 验证 Agent 修改后的增量刷新

让 Agent 创建或修改一个源文件。

预期：

- 不需要完整重扫仓库；
- Agent 的 `changed_paths` 会触发该文件的增量 Repo Map 更新；
- 再打开 Context 面板可看到对应索引结果。

## 9. 缺失 Pin 降级

Pin 一个文件后，在应用外部把该文件暂时改名或删除。

重新打开 Context 面板。

预期：

```text
status = missing
```

而不是整个 Context 功能报错或 Thread 无法继续。

恢复文件后可重新 Pin / Refresh。

## 验收标准

以下正常即可通过 Phase 24：

1. Context 面板正常打开；
2. Repo Map 有文件/符号/语言统计；
3. build/dependency 目录默认被忽略；
4. Pin / Remove 正常；
5. Pin 跨重启持久化；
6. 不同 Thread 的 Pins 相互独立；
7. `@file` 当前轮上下文正常；
8. Refresh Repo Map 后 revision 更新；
9. Agent 修改文件后索引可增量刷新；
10. Pin 文件缺失时只显示 missing，不导致 Turn 失败。
