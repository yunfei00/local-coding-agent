# v0.2 Phase 18 — Diagnostics 人工验收

> 分支：`feature/v0.2`
>
> 自动化已覆盖诊断字段、数据库统计、项目识别、错误环形记录、Home 路径替换、Provider URL 凭证/query 脱敏、API Key/Prompt Rule/聊天正文不进入报告，以及 Desktop 二次脱敏。本页只验证真实桌面页面和 Windows 剪贴板。

## 1. 启动

Windows PowerShell：

```powershell
git checkout feature/v0.2
git pull
.\scripts\dev\start.ps1
```

打开一个已有项目。

## 2. 打开 Diagnostics

点击右上角 `Diagnostics`。

应看到：

- Application
- Platform
- Provider
- Context
- Workspace
- Database
- Prompt Rules
- Recent sanitized errors
- Redaction active

其中应能看到当前 Provider、模型、Context window、Permission、项目类型、数据库 schema / quick check 等信息。

点击 `Refresh` 后页面应正常刷新，不影响当前 Thread 和聊天内容。

## 3. 验证脱敏预览

展开 `Preview copied report`。

重点确认：

1. 不包含 API Key 明文。
2. 不包含聊天正文。
3. 不包含 Prompt Rule 正文，只显示 configured / enabled 状态。
4. 用户 Home 路径应显示为 `<HOME>`。
5. Provider URL 不应包含用户名、密码、API Key query 参数。
6. 数据库只显示 schema、大小、quick check、数量统计，不显示消息内容。

## 4. 验证 Copy report

点击 `Copy report`。

按钮应短暂显示 `Copied`。

打开 Windows 记事本，按：

```text
Ctrl + V
```

应能粘贴一份以：

```text
Local Coding Agent Diagnostics
Generated report is redacted for support sharing.
```

开头的诊断报告。

报告内容应与页面预览一致，并继续满足上面的脱敏要求。

## 5. 验证页面状态

关闭 Diagnostics 后：

- 当前 Project 不变；
- 当前 Thread 不变；
- 原聊天记录仍在；
- 输入框内容和正常聊天功能不受影响。

## 验收结论

以上正常即可认为 Phase 18 人工验收通过。

最重要的验收点只有两个：

1. `Copy report` 在真实 Windows 剪贴板可用；
2. 复制内容中没有 API Key、Prompt Rule 正文和聊天正文。
