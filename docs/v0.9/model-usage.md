# 本轮模型使用与证据

用户禁止 `qwen3.8-flash`、`qwen3.7-plus`，包括别名。本轮真实驱动还支持 `--allowed-model` 正向白名单，未放行的 ID 不调用。Provider 原禁止规则保持最高优先级。不安装或真实连接 Ollama。

本轮先读取已保存配置：只有 `kimi-k3` 与提供的白名单完全匹配。其文本能力检查真实返回 HTTP 400，工具未测试，结果 BLOCKED，不静默使用别名。新增诊断只记录经过字符白名单校验的服务端 code/type/param，不保留敏感错误正文。

同一已有连接的实时模型目录包含 `deepseek-v4-pro-0813` 和 `qwen3.8-2.4t-a95b`。在隔离验收副本中建立候选 profile，用户原始 Endpoint、Key、模型配置和额度未改动。二者文本与工具探针均通过，4 次请求合计服务端 Usage 1,086 Token。

Python 工作流使用 Qwen 规划/审查、DeepSeek 开发/测试，实际角色切换与工具记录保留。首次权限失败及验收驱动契约失败均保留。恢复后原运行累计 14 次调用、126,597 Token；只核对已完成任务的补验前后调用数相同，没有重新开发。

额度快照不是当前余额保证。额度耗尽停止当前模型，遵守原有限回退和剩余预算。额度回退跨角色快照已有 Mock 集成验证，未刻意耗尽真实模型额度。

原轮次去重 92 次业务请求、5 次能力请求；解锁后 GUI 使用 qwen3.8-2.4t-a95b 追加 17 次（218,332 实际 Token），合计 114 次模型 HTTP 请求，另 1 次目录 GET。已知实际输入/输出共 1,329,344 Token，缓存 275,200 是输入子集。一次取消的 Qwen 调用保留 42,727 预留、kimi 失败调用估算 10,256，均未计为准确实际 Usage。费用 UNKNOWN。真实 React、修复、中断恢复、WebSocket 和 Windows GUI 结果见 [综合验收](integrated-acceptance.md)。
