# 逻辑多 Agent

四个角色共享同一个 Runtime 与工具注册表，不创建四套后端进程。

| 角色 | 执行范围 | 完成依据 |
| --- | --- | --- |
| Planner | 读取文件、检索、Git 状态与 Diff、细化未执行计划 | 实际读取证据与计划验收标准 |
| Developer | 既有工作区权限允许的实现与修复 | 持久化工具结果 |
| Reviewer | 独立只读检查 | 重新读取证据及 `workflow_review` 结论 |
| Tester | 允许的测试/构建命令与读取 | 真实命令成功退出码 |

后端在工具分发前再次检查角色权限，隐藏 Schema 不能替代后端约束。Planner/Reviewer 不展示通用终端工具；一次越界终端输出可得到有界纠正，写文件等越权操作直接拒绝。

Reviewer 的 approved 必须关联当前步骤的真实读取证据。request_changes 插入 Developer 修复；复审必须有新的读取证据。测试失败退回 Developer，再插入新的 Reviewer，最后回到 Tester。环境问题不触发无限代码修复。

设置中“自主工作流 · 角色与模板”可以独立绑定四个角色。缺省沿用聊天模型，同一模型可承担多个角色。运行开始后保留角色配置和 Provider 快照，设置变化不应修改已运行任务。模型切换不清零账本。

交接持久记录输入步骤、角色、实际模型和开始时间；完成后追加真实证据 ID、变更路径及完成时间。模型额度回退同时更新运行内部的角色快照，后续交接不会重新选择已耗尽模型；此故障场景以 Mock 验证，未为验收刻意耗尽真实额度。没有打开项目时也能配置角色和查看模板，不需要创建空线程。
