# 自动开发、审查、测试与修复

流程为 Planner 工程检查 → Developer 实现 → Reviewer 独立审查 → Tester 真实测试。仍由原 VerificationEngine 根据工程实际配置和变更选择验证，修改代码后默认开启；不假设所有工程都有 pytest/npm。

验证记录命令、退出码、类别、摘要、日志及耗时，独立程序验证同样计入工具预算。测试文字不作为通过依据。Reviewer 不允许写源码；Tester 不允许修改测试或配置来制造通过。

代码失败可有限修复；网络、依赖、配置、权限、取消及超时与代码错误区分。失败签名包含验证结果和工作区内容指纹，相同问题无变化达到阈值时停止。默认审查修复 3 轮、无进展 2 次，可在工作流设置中调整到有界值；原工具、请求、Token、时间及恢复上限继续生效。

达到限制保存计划和 Checkpoint，保留失败证据。没有测试、测试未通过或测试环境阻断时，不标记为已验证交付。
