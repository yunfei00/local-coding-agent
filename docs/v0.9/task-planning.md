# 依赖计划

每个工作流步骤保留原持久化 step ID、description、verification、state、evidence，并增加本地图 ID、标题、依赖、能力要求、角色、验收标准及 retry_count。

整张图写入前检查重复 ID、不存在依赖、自依赖、循环和最多 30 节点限制。缺省依赖为前一节点，显式空数组表示独立节点。调度优先继续已开始且依赖就绪的节点；只有完成的依赖才能解锁后续任务，跳过不冒充完成。

`revise_workflow` 只调整 pending 节点的允许字段，整图先验证再写入并保存调整原因。已完成节点的状态、证据和 ID 不被覆写。审查/测试退回通过插入新的修复节点更新依赖，不把已完成开发节点重新变成 Blocked。

统一入口向 Planner/Developer 提供 `workflow_adjust`，可以根据真实工程检查细化尚未开始步骤的描述、验证命令、依赖及验收要求；不能改变既有角色或已经开始/完成的节点。一次运行最多成功调整 3 次，必须单独调用，整图验证失败不写入。此原生入口已通过 Mock Provider 的实际工具、文件修改和 unittest 闭环；本轮在线模型没有另行重跑动态调整专项。

预算复用同一 ExecutionBudget，总预算不按角色重置；每个角色的保守 Token 预留记录为 `workflow:<role>` 阶段，受已有阶段及总额度约束。尚未提供独立的每节点金额额度编辑器。
