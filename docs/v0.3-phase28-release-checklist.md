# v0.3 Phase 28 — Release Candidate 验收与发布操作手册

> 目标：在 v0.3 发布前完成全量回归。所有命令从仓库根目录运行；不得在 RC 验收前合并 main 或创建正式 tag。

## 1. 获取代码

```powershell
git checkout feature/v0.3
git pull --ff-only origin feature/v0.3
git status --short
```

要求工作区无意外改动。

## 2. 自动化回归

```powershell
python -m unittest discover -s tests -v
cd desktop
npm ci
npm run build
cd ..
```

核对 GitHub Actions 的 Windows 与 Ubuntu CI 都通过。失败时保留日志，不进入发布。

## 3. Windows 构建

查看 `scripts/build/package-windows.ps1` 的参数及 `.github/workflows/package-windows.yml`。优先运行 GitHub 打包 workflow，下载 Windows Setup 与 Portable。安装包与 Portable 必须分别进行首次启动和 Agent 连接测试。

## 4. v0.2 升级保留性

使用 **v0.2 数据目录的备份副本**，禁止直接拿生产数据测试：

1. 备份数据库、项目清单、Threads、Prompt Rules 和 MCP 配置。
2. 用 v0.3 打开副本，确认数据迁移不丢失。
3. 检查项目、会话、设置、Prompt Rules 数量和内容一致。
4. 重启再验证一次；任何不可逆迁移必须有恢复方案。

## 6. SHA256 校验

下载最终发布产物后，在 PowerShell 中执行：

```powershell
Get-FileHash .\Local-Coding-Agent-Setup.exe -Algorithm SHA256
Get-FileHash .\Local-Coding-Agent-Portable.zip -Algorithm SHA256
```

文件名须替换为实际产物名称；与 Release 附件的 `SHA256SUMS` 对照，不允许虚构校验值。
