# 中断与恢复

后端启动复用原 Task recover，并扫描普通统一运行的活动阶段。遗留运行变为 paused/BACKEND_INTERRUPTED；模型/预算/执行证据保留，未结算外部请求改 interrupted，保留保守预留。不自动发模型请求。

## 同页操作

1. 打开原会话，查看当前失败原因、Diff、计划与验证日志。
2. 选择“检查并继续未完成步骤”（有 Plan），或“检查并恢复原运行”（无 Plan）。
3. 原工具权限继续适用。未知副作用通过原检查/审批处理，不能直接重放危险命令。
4. Stop 终止当前尝试和其工具进程；需要用户明确恢复后才启动新 generation。

恢复使用原目标和 `unified_config`、`unified_provider_snapshot`；Settings 变化只作用于新运行。预算累计保留，不因重启清零。单运行恢复次数默认最多 3 次，不以反复恢复绕过循环保护。

## 预算与未知结果

任务计划的“增加执行预算”可以编辑调用与 Token 增量，默认 16 次、500000 Token，并增加 300 秒和一次续跑。可选“同时追加本运行的全局预检上限”；这是原任务快照的明确调整，不改日常 Settings，也不重置已用量或扩大费用上限。整体执行器最多 512 次调用，仍保留时间、重复操作与无进展保护。

出现 PLAN_UNCERTAIN_EFFECTS 时点击“核对中断操作”，查看 Diff 和日志，再对具体记录选择“审阅中断记录”。该操作会通过原审批系统再次明确授权。记录保留为 reviewed，结果仍未知，不认定成功、不自动重放；后续修改继续要求明确审批。只有新的实际验证与完整步骤证据才能完成任务。真实解决阻断的这次审阅建立新的恢复机会，重复审阅同一条记录不能反复清零恢复次数。

新运行仍可独立开始。旧版本未保存完整目标的无 Plan 运行不能猜测恢复，给出 LEGACY_GOAL_UNAVAILABLE，保留历史并让用户重新提出需求。

已有 Plan 幂等、Completed 保护、只读验证可重跑、未知修改需核对均复用 `TaskPlanStore` 与原执行 Journal。普通统一 Chat 使用当前项目目录；不能宣称默认隔离 Worktree，高级 Task 才沿用原 Worktree 流程。
