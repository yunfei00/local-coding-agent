# 会话草稿、新建与删除（2026-10-27）

## 已实现

- 项目右侧使用写入图标打开新会话草稿，不使用加号。添加项目入口使用文件夹图标。
- 桌面打开空项目、反复点击写入图标、输入未提交文字都不创建 SQLite 会话行，也不消耗模型调用。首次发送或提交有内容的自主任务时，复用原 `thread.create` 和执行链路创建一条会话，并用首条内容生成标题；标题生成不调用模型。
- 未提交草稿按项目/会话在当前窗口内存中保留；没有声称已永久保存，重启后以已提交会话为准。
- 会话右键或 `…` 菜单支持 Rename、Delete；支持方向键和 Escape。Delete 有居中确认弹框和 Cancel，失败原因留在弹框中。
- 删除按所属项目校验，不切换到其他项目。删除当前会话后选择剩余会话；删除最后一条后回到空草稿，重启不会自动补出 New thread。
- 删除采用持久化删除标记，从列表移除。项目文件、Worktree、已结算和不确定的 API 账本、任务、Checkpoint 及审计历史保留；本功能不是安全擦除历史数据。确认弹框明确说明会停止该会话的未完成任务，确认后复用原任务取消路径，等待进程清理后才删除导航记录。不会停止其他会话。
- SQLite schema 升到 5；增量添加 `deleted_at`，不重建历史表。旧 Agent API 默认行为保留，桌面 IPC 明确启用延迟创建。

## 删除失败补查

用户反馈删除失败后，代码和自动测试确认旧实现会将 paused / awaiting_approval 等未完成任务统一判为 THREAD_BUSY；先前桌面 smoke 只删除没有任务的会话，遗漏了这个路径。公司机器的具体报错未取得，不将该复现当作其唯一根因。

修复后，桌面确认删除请求明确携带 `cancel_tasks:true`；后端按持久化任务和活动 Turn 的会话归属停止，只在安全停止后添加删除标记。没有明确确认的旧调用仍保留忙碌保护。重复删除返回成功，防止响应丢失后重试误报；删除已成功而列表刷新失败时明确显示刷新问题。任务没有本机所有者、停止超时或停止期间开始新执行时保留会话并给出具体原因。

最终审查补充清理异常保护：`gather(return_exceptions=True)` 的返回值不能当作清理成功；自主任务 finally 中的进程清理异常不能吞掉。现在会持久化清理错误并暂停、生成诊断，删除等待发现失败时保留会话；重复点击也不会跳过已知的清理失败。此路径用故障注入验证，不声称本机真的有无法终止的进程。清理失败属于需要检查保留进程日志的恢复情形，没有自动强制删除或清除保护的界面。

Vite 刷新只更新页面，不能更新 Electron 主进程/预加载或 Python 后台。旧进程缺少删除 IPC 时会提示完整退出、重建并重启，不再只显示难懂的远程方法异常。用户已有配置无需清空。此修复属于源码更新，没有发布安装包。
