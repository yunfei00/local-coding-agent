# v0.2 Development Roadmap

Branch: `feature/v0.2`  
Stable baseline: `v0.1.0` / `main` at `c1a56cca43f57e5c7a50588e87cc43a2d9825e39`

## Guardrails

- `main` and `v0.1.0` remain untouched until v0.2 is explicitly accepted.
- All v0.2 work lands on `feature/v0.2`.
- Every phase must pass the existing Windows + Ubuntu CI matrix.
- Existing tests stay green and new behavior gets regression tests.
- Packaged Renderer and bundled Agent smoke tests remain release gates.
- Permission/Approval rules continue to apply to risky operations.
- The Agent never commits or pushes on its own unless the user explicitly requests it.
- v0.2 does not include MCP, SSH Remote, Multi-Agent, semantic vector indexing, a full Monaco editor, or a Plugin Marketplace.

## Phase 10 — Provider foundation + OpenAI-compatible provider

Scope:
- Introduce a provider-neutral interface/error contract.
- Keep Ollama as the default provider.
- Add an OpenAI-compatible provider supporting model discovery, streaming chat completions, content deltas, tool calls, usage, and common error handling.
- Add provider factory/configuration through environment variables as the backend foundation for the later Settings page.
- Never expose API keys in status/diagnostic payloads.
- Remove server assumptions that every provider is Ollama.

Acceptance:
- Ollama tests remain green.
- OpenAI-compatible mock server tests cover model listing, auth, streaming content, streamed tool-call arguments, usage, and failures.
- Agent server can boot with either provider without code changes.
- Existing desktop behavior still works with Ollama.
- Windows + Ubuntu CI pass.

Depends on: v0.1.0 baseline only.

## Phase 11 — Prompt Rules hierarchy

Scope:
- Global, Project, and Thread rules with deterministic precedence.
- Effective prompt assembly: built-in safety/runtime prompt -> global rules -> project rules -> thread rules -> runtime workspace/permission context.
- Persistence and CRUD protocol.
- Rule enable/disable/reset support.
- Rules may guide the Agent but cannot override permission/approval enforcement.

Acceptance:
- Persistence survives restart.
- Precedence and prompt composition are unit tested.
- Switching projects/threads applies the correct effective rules.
- Permission tests prove rules cannot bypass high-risk controls.
- Windows + Ubuntu CI pass.

Depends on: Phase 10 provider-neutral prompt path.

## Phase 12 — Context budget manager

Scope:
- Replace simple unbounded history growth with an explicit context budget.
- Preserve system/rules, recent user/assistant turns, unresolved tool state, and latest verification context.
- Compact older turns/tool outputs with deterministic truncation first; add summarization hooks without requiring a second model.
- Expose context usage metadata to the desktop.

Acceptance:
- Long synthetic conversations stay under configured budget.
- Latest user intent and recent tool results are preserved.
- No infinite history growth in SQLite-to-model assembly.
- Existing short conversations are behaviorally unchanged.
- Windows + Ubuntu CI pass.

Depends on: Phase 11 prompt assembly.

## Phase 13 — Agent Loop reliability

Scope:
- Strengthen identical-call and short-cycle repeat detection.
- Track consecutive tool/model failures and stop safely after configurable ceilings.
- Harden retry rules so retries do not duplicate side effects.
- Keep absolute max model steps/tool calls and clean cancellation.
- Improve failure reasons surfaced to UI.

Acceptance:
- Tests cover identical repeats, A/B call cycles, repeated failures, max limits, transient provider retry, cancellation, and successful recovery.
- No automatic commit/push behavior is introduced.
- Windows + Ubuntu CI pass.

Depends on: Phase 12 context metadata; extends existing v0.1 guards.

## Phase 14 — Project detection + search_files v2

Scope:
- Detect Python, Node, Android/Gradle, and CMake projects from workspace markers.
- Produce safe test/build suggestions; do not auto-run destructive/publishing commands.
- Extend `search_files` with glob, regex, exclude patterns, result limits, and before/after context.
- Respect workspace/full-access/read-only permissions.

Acceptance:
- Fixture-based detection tests for all four project families and mixed repos.
- Search tests cover glob/regex/exclude/context and path boundaries.
- Suggested test commands are inspectable and deterministic.
- Windows + Ubuntu CI pass.

Depends on: Phase 13 loop behavior.

## Phase 15 — Terminal / Tool Stream

Scope:
- Structured stdout/stderr streaming with sequence numbers and final summary.
- Better long-running command status, cancellation, truncation/backpressure, and process-tree termination visibility.
- Desktop tool cards show live output without destabilizing the chat scroll.

Acceptance:
- Ordered stream tests, large-output truncation tests, cancel tests, and process-tree regression tests.
- UI remains responsive during verbose commands.
- Windows + Ubuntu CI pass.

Depends on: Phase 13 event/failure conventions.

## Phase 16 — Diff / Review v2

Scope:
- Per-file change list with status and line stats.
- Select a file to inspect its patch independently.
- Clearer additions/deletions, rename/binary/large-diff handling, and final review state.
- Review remains read-only; edits still happen through approved tools.

Acceptance:
- Multi-file, rename, binary, empty-diff, and large-diff cases are tested.
- User can move between changed files without losing chat/thread state.
- Windows + Ubuntu CI pass.

Depends on: Phase 15 stream/UI event cleanup.

## Phase 17 — Settings page

Scope:
- General, Provider, Agent, Context, Prompt Rules, and Safety sections.
- Configure Ollama/OpenAI-compatible provider, base URL, model, context window, and non-secret defaults.
- API keys must not be stored as plaintext in SQLite; prefer OS-protected Electron storage when available, otherwise session/environment-only behavior.
- Settings validation and reset-to-default.

Acceptance:
- Settings round-trip through desktop/backend.
- Provider switch has a safe validation flow.
- Secrets are redacted from protocol logs/diagnostics.
- Existing v0.1 startup defaults still work without migration action.
- Windows + Ubuntu CI pass.

Depends on: Phases 10–12.

## Phase 18 — Diagnostics

Scope:
- Diagnostics page with app/protocol versions, platform, provider status, selected model, context settings, workspace metadata, project detection, database path/status, and recent sanitized errors.
- One-click copy of a redacted diagnostic report.

Acceptance:
- Diagnostic report contains no API key/token/approval secret or full sensitive prompt history.
- Copy action works in packaged desktop.
- Windows + Ubuntu CI pass.

Depends on: Phase 17 settings and Phase 14 project detection.

## Phase 19 — Update-check foundation + Codex-style UI polish

Scope:
- Add a disabled-by-default/manual update-check service boundary that can query release metadata later.
- No auto-download or auto-install in v0.2.
- Continue Codex Desktop-style spacing, navigation, provider/status presentation, thread/tool/diff ergonomics, and empty/loading/error states.

Acceptance:
- Update checks can be invoked manually and fail safely/offline.
- No update is installed without explicit user action.
- Main flows remain keyboard-friendly, including Enter-to-send behavior.
- Windows + Ubuntu CI pass.

Depends on: Phases 16–18.

## Phase 20 — v0.2 hardening / release candidate

Scope:
- Full regression pass from v0.1 plus all v0.2 tests.
- Windows Setup + Portable build.
- Bundled Agent smoke test and packaged Renderer smoke test.
- Fresh install, upgrade-over-v0.1, SQLite migration, offline Ollama startup, OpenAI-compatible configuration, Stop/process-tree, permissions, Diff Review, Settings, and Diagnostics acceptance.
- Prepare release notes and checksums only after explicit approval to release.

Acceptance:
- Windows + Ubuntu CI green.
- Setup and Portable artifacts both launch successfully.
- SHA256SUMS generated and verified.
- No `main` merge, tag, release, commit/push by the Agent unless explicitly requested.
- v0.1.0 artifacts remain unchanged.

Depends on: Phases 10–19.
