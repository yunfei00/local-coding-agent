> 固定人工验收工程：`manual-fixtures/phase26-task-plan`
>
> 状态：验收材料已准备；**尚未完成人工验收**。当前计划系统支持手动创建与编辑，不能把计划面板理解为 Agent 自动规划或自动恢复执行。

## 1. 更新代码并准备固定工程

在 Local Coding Agent 仓库根目录打开 PowerShell：

```powershell
git checkout feature/v0.3
git pull
.\manual-fixtures\phase26-task-plan\setup.ps1
```

脚本会输出类似：

```text
C:\Users\you\AppData\Local\Temp\lca-phase26-plan-demo-20261009-123456
```

**只在 Local Coding Agent 中打开脚本打印的临时目录**，不要打开原始 fixture，也不要打开整个 local-coding-agent 仓库。

## 2. 启动应用

```powershell
.\scripts\dev\start.ps1
```

打开临时项目，使用默认 Thread，点击顶部 **Plan**。预期右侧出现 `Thread plan` 面板，不影响左侧导航和聊天输入框。

## 3. 创建固定任务计划

在 Plan 面板输入：

```text
Goal: 修复计算器加法错误并验证
Steps:
检查 src/calculator.py 和测试
运行 python -m unittest discover -s tests -v，确认失败
修复 add 的实现
再次运行测试，确认通过
检查 git diff 和 git status
```

点击 **Create plan**。

预期显示 5 个按顺序排列的步骤，初始均为 `pending`。新建短对话无需强制创建计划。

## 4. 验证 Thread 隔离

新建 Thread，点击 Plan。预期该 Thread 的计划列表为空。切回原 Thread，原来的计划和五个步骤仍然存在。

## 5. 验证跨重启持久化

关闭应用，重新执行 `start.ps1`，打开同一个临时工程及原 Thread。

预期 Plan 中仍有原来的目标与五个步骤，顺序和状态保持不变。

## 6. 验证状态更新及完成证据

在原计划选择第一步，改成 `in_progress`，预期状态更新。

选择 `completed` 时会要求输入验证证据。取消或输入空内容，预期步骤**不能**标记为完成。

提供真实证据，例如：

```text
已检查 src/calculator.py 和 tests/test_calculator.py
```

预期步骤状态变成 `completed`。

**注意**：此项目前验证的是 UI 输入证据与持久化门槛；尚不能视为自动验证运行时工具结果。

## 7. 验证固定项目失败基线

在聊天发送：

```text
先不要修改文件。读取 src/calculator.py 和 tests/test_calculator.py，然后运行 python -m unittest discover -s tests -v，报告真实失败结果。
```

预期测试失败，至少 `add(2, 3)` 预期 5、实际 -1。不得声称通过。

## 8. 验证修改和成功测试

发送：

```text
修复 src/calculator.py 中 add 的实现，只做必要修改。运行 python -m unittest discover -s tests -v，并检查 git diff 与 git status。不要 commit 或 push。
```

预期：
- `add` 使用加法，测试通过；
- Git diff 只包含预期修改；
- 不发生自动 commit/push。

将对应步骤状态更新，并为完成的步骤提供实际测试命令及结果作为证据。

## 9. 验证检查点

点击计划中的 **Checkpoint**，然后点击 **Resume info**。

预期可以读取最近一次检查点的原因，不会自动重复运行命令或再次修改文件。

## 10. 验证取消执行后的检查点

在聊天中发送一个需要多步工具调用的只读检查任务；在执行过程中点击 Stop。

预期该 Thread 的未完成计划获得 `turn_cancelled` 检查点；点击 **Resume info** 可查看原因。

**注意**：如果任务执行太快而无法点击 Stop，此项记录为未测，不要判为通过。

## 11. 验证完成执行后的检查点

在聊天中执行一个正常结束的检查任务，完成后点击 **Resume info**。

预期未完成计划最近检查点原因更新为 `turn_completed`。

## 12. 验证计划不会绕过权限

在 Permission 设为 Read only 时，不应允许修改文件。即使计划包含修改步骤，仍以运行时权限为准。

普通任务不得自动 commit 或 push；显式 commit 仍需要独立 Approval。

## Phase 26 人工验收标准

1. Plan 面板能打开与关闭，聊天输入不受影响；
2. 创建计划后步骤数量与顺序正确；
3. 计划按 Thread 隔离；
4. 重启后计划仍存在；
5. 状态更新可保存；
6. 没有证据不能标记完成；
7. Demo 初始测试确定失败；
8. 修复后测试通过，且未自动 commit/push；
9. 检查点可保存和读取；
10. 取消或正常结束的执行可留下对应检查点；
11. 权限控制仍生效。

- 完整步骤编辑和排序的桌面交互。
