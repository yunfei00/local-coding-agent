# v0.2 Phase 16 — Diff / Review v2 人工验收

> 分支：`feature/v0.2`
>
> 自动化测试已经覆盖 modified / deleted / untracked / staged rename / binary / large diff / empty diff / 路径带空格。本文只验证桌面交互。

## 1. 启动当前分支

Windows PowerShell：

```powershell
git checkout feature/v0.2
git pull
.\scripts\dev\start.ps1
```

## 2. 创建一次性 Diff 测试仓库

另开一个 PowerShell：

```powershell
$root = Join-Path $env:TEMP ("lca-phase16-" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path $root | Out-Null
Set-Location $root

git init -q
git config user.email "phase16@example.test"
git config user.name "Phase 16"

Set-Content normal.txt "before"
Set-Content "rename me.txt" "rename-content"
[IO.File]::WriteAllBytes((Join-Path $root "blob.bin"), [byte[]](0,1,2,3))
git add .
git commit -q -m "initial"

Set-Content normal.txt "after"
Rename-Item "rename me.txt" "renamed file.txt"
[IO.File]::WriteAllBytes((Join-Path $root "blob.bin"), [byte[]](0,9,8,7))
1..1000 | ForEach-Object { "line-$_" } | Set-Content large.txt

Write-Host $root
```

记住最后打印的路径。

## 3. 验证 Working Tree Review

在 Local Coding Agent 中打开上面的临时仓库，然后发送：

```text
只查看当前 Git diff，不修改任何文件。请调用 git_diff。
```

应看到新的 Review 卡片：

1. 顶部显示文件总数和总 `+/-`。
2. 显示 `Read only`。
3. 左侧为文件列表，右侧只显示当前选中文件 patch。
4. 点击不同文件，右侧 patch 会切换，对话和 Thread 不会变化。
5. `blob.bin` 显示 binary 提示，不显示乱码。
6. `large.txt` 显示 limited / Partial preview，不会把 1000 行全部铺满。
7. 普通文本修改能看到正确行号、增加行和删除行。
8. 未 stage 的直接文件改名允许显示为 deleted + untracked，这是 Git 的真实 working-tree 语义。

## 4. 验证 Staged Rename

在刚才的临时仓库 PowerShell 中执行：

```powershell
git add -A
```

然后在 Agent 中发送：

```text
只查看 staged Git diff，不修改文件。请调用 git_diff，并设置 staged=true。
```

应看到：

1. `renamed file.txt` 状态为 `R` / `renamed`。
2. 右侧显示 `rename me.txt → renamed file.txt`。
3. 显示 similarity（通常 100%）。
4. 文件仍然只能审查，Review 卡片中没有直接修改按钮。

## 验收结论

以上交互正常即可认为 Phase 16 人工验收通过。

临时目录不再需要时，可以自行删除。
