# 权限模型

序列化保持 read_only / workspace / full_access，界面显示只读、工作区、完全访问。READ_ONLY 不允许写入和有副作用的终端命令；WORKSPACE 工程内普通操作可执行，外部路径须本次审批；FULL_ACCESS 由用户明确一次确认后连续执行普通文件、终端、Git、MCP和目标窗口工具。

任务临时授权 > 项目覆盖 > 全局默认。聊天工具栏修改当前任务或项目，设置中可修改全局默认、当前项目或当前任务覆盖。新工程继承全局。运行中可撤销，新操作重新检查；已经发生的操作不会被自动撤销，可另行停止任务。

v0.9 Full Access逐项审批与新语义不同，旧值保留，但不能静默升级为连续授权。首次启用新语义仍确认一次，重启不会反复确认。

Reviewer/Planner 的角色限制、工作流冻结验收文件、未知副作用重试确认、桌面窗口绑定、敏感控件/UAC/锁屏保护继续生效。递归批量删除、force push、系统/发布高风险仍单独授权，禁用系统保护和明显凭据读取/外传阻断。整屏截图额外确认；普通脱敏窗口截图可按一次完全授权用于任务配置的模型服务。

权限表不保存工具参数、文件内容或API Key。终端风险识别是规则启发式，不是Windows OS沙箱，不能宣称防御任意恶意工程脚本。请仅运行可信工程和MCP。

## 验收边界

真实安装版在线任务已验证文件修改、终端测试、Planner/Developer/Reviewer/Tester交接不重复请求普通审批；撤销为只读后，后续写文件任务被拒绝，目标文件没有生成。被拒任务保持失败状态，不伪造为完成。

安装版权限专项另有4项IPC/重启检查：拒绝首次确认不授予权限、允许后连续切换不重复确认、重启后恢复、撤销。该专项的原生对话框选择由测试Mock，主进程IPC与后端是真实的；不能将它描述为真实鼠标点击系统确认框。

Git保护新增测试覆盖force标记、`+HEAD:main`、`:main`远程删除refspec和mirror等高风险形式；完全访问不会把这些操作自动降级为普通push。测试没有执行远程破坏性操作。
