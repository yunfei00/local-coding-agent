# v0.3 Phase 27 — 执行与上下文观测操作文档

> 开发分支：feature/v0.3。本文同时记录已实现项与尚未接入项，不能把组件级测试当作整机验收。

## 目标

每轮任务展示模型/Provider、模型轮次、工具次数与耗时、失败与重试、上下文 Token 估算和来源；Diagnostics 展示 MCP / Worktree / Repo Map 健康状态；复制脱敏执行轨迹，不记录隐藏推理内容。

## 已落地的基础模块

- Python `agent/core/turn_metrics.py`：独立、定长的执行统计对象（尚需完整接入 Agent 运行循环）。
- Desktop `desktop/src/lib/diagnostics.ts`：`formatTurnTrace` 只导出白名单字段，诊断脱敏保留普通 Token 计数。
- Python / Desktop 测试验证统计结构和敏感字段过滤。

## 开发环境检查（Windows PowerShell）

```powershell
git checkout feature/v0.3
git pull --ff-only origin feature/v0.3
python -m unittest discover -s tests -p "test_turn_metrics.py" -v
cd desktop
npm ci

cd ..
```

若项目使用的 npm 测试脚本与以上不同，以 `desktop/package.json` 为准。

## 运行时验收（接入完成后执行）

1. 使用 `scripts/dev/start.ps1` 启动应用并打开测试工程。
2. 发起包含至少两次工具调用的任务，记录 Provider、Model、model_steps、tool_calls、tool_duration_ms、tool_failures、provider_retries。
3. 人为制造一次被权限拒绝的工具调用，验证失败计数递增且不会暴露参数或密钥。
4. 检查上下文来源中 pinned、repo map、history 等占用，核对预算使用。
5. Diagnostics 复制轨迹，搜索 `Bearer`、`sk-`、`password` 和本地秘密值，必须全部脱敏。
6. 重启应用，检查诊断统计不会无限累积。
