# v0.1.0 实施计划

## 1. 版本定位

v0.1.0 是 Local Coding Agent 的第一个可用版本。

目标不是复制一个 Codex 外观，而是完成一个真正可用于本地软件开发的 Agent 闭环：

```text
用户任务
  -> Agent 分析
  -> 调用工具
  -> 读取结果
  -> 修改代码
  -> 执行测试
  -> 根据结果继续迭代
  -> 完成任务
```

首发平台：Windows 10 / Windows 11。

首发模型后端：Ollama。

首发工作目录：本机 Git 仓库。

---

## 2. v0.1.0 Definition of Done

只有同时满足以下条件，v0.1.0 才算完成：

- 桌面应用可在 Windows 启动。
- 可以选择任意本地项目目录。
- 可以检测本机 Ollama 服务。
- 可以读取 Ollama 已安装模型并切换模型。
- 可以创建、保存、恢复 Thread。
- 可以提交一个 Turn 并流式显示回复。
- Agent 能自主调用文件、搜索、Shell 和 Git 工具。
- Agent 能根据 Shell 错误继续下一步，而不是一次回复后结束。
- Agent 可以修改工作区文件。
- 文件修改能以 Diff 形式展示。
- 高风险操作能够触发用户确认。
- 可以中止正在执行的 Turn。
- 应用关闭后重新打开，能够恢复最近项目和会话。
- 在至少一个真实项目完成一次：
  - 运行失败测试；
  - 定位问题；
  - 修改代码；
  - 重跑测试；
  - 测试通过；
  - 输出变更总结。
- 基础自动化测试和 GitHub Actions CI 通过。

## 3. 开发阶段

目标：建立可持续开发的仓库，而不是先堆业务代码。

任务：

- 初始化 Electron + React + TypeScript。
- 初始化 Python Agent 包。
- 定义 desktop / agent / shared / tests / scripts / docs 目录。
- 增加根目录开发启动脚本。
- 增加格式化、Lint 和基础测试配置。
- 增加 GitHub Actions。
- 建立版本信息。
- 建立日志目录规范。
- 建立环境检测脚本。

验收：

- 一条命令能够启动 Desktop。
- 一条命令能够单独启动 Agent Server。
- CI 能完成前端和 Python 基础检查。
- Desktop 能检测 Agent Server 是否在线。

建议里程碑：`v0.1-phase0`

目标：真正接入本地大模型。

任务：

- 检测 `http://127.0.0.1:11434`。
- 获取本地模型列表。
- Provider 抽象。
- Ollama Provider 实现。
- 流式输出。
- 超时与断线处理。


- 切换模型后下一 Turn 生效。
- 模型可以流式输出。
- Ollama 未启动时给出明确错误。
- Agent Core 不依赖具体模型名称。

建议里程碑：`v0.1-phase2`

### Phase 3：Tool System v1

目标：让模型真正操作本机项目。

#### 文件工具

- `list_directory`
- `read_file`
- `write_file`
- `apply_patch`
- `search_files`
- `file_exists`

约束：

- 默认只允许访问当前 Workspace。
- 路径统一做绝对路径解析和边界校验。
- 大文件必须限制读取大小。
- 二进制文件不直接按文本修改。

#### Shell 工具

- `run_command`
- `stop_command`

要求：

- Windows 默认 PowerShell。
- 支持工作目录。
- stdout / stderr 实时流式返回。
- 支持 exit code。
- 支持超时。
- 支持中止进程树。

第一版应能执行：

```text
git
python
pytest
pip
node
npm
npx
adb
gradlew.bat
cmake
ninja
docker
ssh
```

工具层不为这些命令写专用实现，它们都通过通用 Shell 执行。

#### Git 工具

- `git_status`
- `git_diff`
- `git_log`

v0.1.0 不自动执行：

- git push
- git reset --hard
- git clean -fd
- 强制 checkout 覆盖改动

验收：

- Agent 可查看目录。
- Agent 可读取源码。
- Agent 可搜索关键词。
- Agent 可运行测试。
- Agent 可修改源码。
- Desktop 可看到工具调用及结果。

建议里程碑：`v0.1-phase3`

---

### Phase 4：Agent Loop

目标：从“聊天机器人 + 工具”升级为真正的 Coding Agent。

核心循环：

```text
接收用户任务
  -> 构造上下文
  -> 调用模型
  -> 模型请求工具
  -> 权限检查
  -> 执行工具
  -> Tool Result 回填
  -> 再次调用模型
  -> ...
  -> 模型返回完成状态
```

需要实现：

- 最大循环步数。
- Turn 总超时。
- Tool 错误可恢复。
- Shell 非零退出码不自动等同于 Agent 失败。
- 上下文压缩预留接口。
- 重复工具调用保护。
- 用户 Stop。
- 系统提示词。
- Workspace 信息注入。
- Git 状态注入策略。
- 最终总结。

第一版成功标准：

用户输入：

```text
运行这个项目的测试，找到失败原因并修复，直到测试通过。
```

Agent 能连续完成多轮 Tool Call，而不是每一步都要求用户手工继续。

建议里程碑：`v0.1-phase4`

---

### Phase 5：权限与审批

目标：Agent 有能力，但不能无边界执行。

#### Read Only

允许：

- 浏览目录
- 读取文件
- 搜索
- git status / diff / log
- 只读 Shell 命令

禁止：

- 写文件
- 删除文件
- 安装软件
- 修改系统

#### Workspace

允许：

- 当前 Workspace 内读取和修改。
- 执行项目开发命令。
- 创建项目内文件。

需要审批：

- 删除较多文件。
- Workspace 外写文件。
- 明显破坏性 Git 命令。
- 系统级安装或配置。

#### Full Access

允许更大的本机访问范围，但危险行为仍可要求审批。

第一版必须实现的安全措施：

- Workspace Path Guard。
- 命令危险等级判断。
- Approval Request。
- Allow Once。
- Deny。
- 可选 Allow for Turn。
- 审批行为写入日志。

验收：

- Read Only 无法修改文件。
- Workspace 无法静默写 Workspace 外路径。
- 高风险命令能被 UI 拦截确认。

建议里程碑：`v0.1-phase5`

### Phase 8：真实项目闭环验收

选择至少三个类型的本机仓库进行验证：

#### Case A：Python

任务示例：

```text
运行 pytest，找出失败原因并修复，直到通过。
```

#### Case B：Node / Electron

任务示例：

```text
运行测试和构建，修复导致构建失败的问题。
```

#### Case C：Android

任务示例：

```text
运行 gradlew.bat test 或 assembleDebug，修复代码级错误后重新验证。
```

检查：

- Agent 是否读了正确文件。
- 是否发生无意义全仓库扫描。
- 命令错误是否可继续。
- 是否修改错目录。
- 是否产生重复循环。
- 是否出现上下文爆炸。
- 是否能停止。
- Diff 是否准确。
- 会话恢复是否可靠。

v0.1.0 不要求本地模型在所有复杂项目都达到在线 Codex 水平，但执行框架必须正确、稳定、可观察。

## 4. 开发优先级

按以下顺序开发，不建议改变：

```text
P0 项目骨架
 -> P1 通信
 -> P2 Ollama
 -> P3 Tool System
 -> P4 Agent Loop
 -> P5 权限
 -> P6 UI
 -> P7 持久化
 -> P8 真实项目验收
 -> P9 Windows 打包
```

其中最关键的不是 UI，而是：

```text
Agent Loop + Tool System + Permission + Observable Execution
```

## 5. 第一版 Agent 行为原则

Agent 应：

- 先理解任务，再行动。
- 优先读取必要文件，不盲目读取整个仓库。
- 修改前了解已有状态。
- 不覆盖用户已有未提交修改。
- 命令失败后分析输出再决定下一步。
- 修改后主动验证。
- 验证失败则继续迭代。
- 最终说明做了什么、验证了什么、还存在什么问题。

Agent 不应：

- 默认执行 destructive commands。
- 无理由删除大量文件。
- 自动 push。
- 自动提交用户没有要求的 commit。
- 假装测试成功。
- 隐藏命令失败。
- 在项目外任意修改文件。

## 8. 日志与可观察性

v0.1.0 必须从一开始就记录：

- Thread ID
- Turn ID
- Provider
- Model
- Tool name
- Tool arguments 摘要
- Tool duration
- Exit code
- Approval
- Error
- Token / context 信息（Provider 可提供时）
- Turn 总耗时

默认不要在日志中保存：

- Token
- Password
- 私钥
- 环境变量中的明显敏感值

## 10. 开发启动约定

规划完成后：

1. `main` 保留本次规划作为基线。
2. 创建 `feature/v0.1-mvp`。
3. 从 Phase 0 开始。
4. 每完成一个 Phase：
   - 本地测试；
   - CI；
   - 人工验收；
   - 记录状态；
   - 再进入下一 Phase。
5. v0.1.0 全部通过后再合并 main 并打正式 Tag。

不要在 v0.1.0 开发中同时加入大量后续功能，以免 Agent Core 尚未稳定就产生架构负担。
