# v0.3 Phase 25 — Git Workflow v3 + Task Worktree 验收

> 分支：`feature/v0.3`
>
> 固定人工验收工程：
>
> ```text
> manual-fixtures/phase25-git-workflow
> ```

## 1. 更新并创建固定 Git 工程

在 local-coding-agent 仓库根目录执行：

```powershell
git checkout feature/v0.3
git pull
.\manual-fixtures\phase25-git-workflow\setup.ps1
```

脚本会打印一个临时目录，例如：

```text
C:\Users\you\AppData\Local\Temp\lca-phase25-git-demo-20261009-123456
```

在 Local Coding Agent 中 **Open project**，打开这个目录本身。

## 2. Git 面板固定基线

点击顶部：

```text
Git
```

预期：

```text
Branch = main
Staged = 0
Unstaged = 0
Untracked = 0
Working tree = Clean
```

Local branches 至少有：

```text
main             Current
phase25/reference
```

Worktrees 初始只包含源工作树。

## 3. 验证 stage

在聊天中发送：

```text
把 src/app.py 的 greeting 返回值改成 "phase25", 然后只 stage src/app.py，不要 commit。
```

预期：

- Agent 修改 `src/app.py`；
- Agent 使用结构化 `git_stage`；
- 不出现 Git commit；
- Git 面板 Refresh 后：

```text
Staged = 1
src/app.py
```

## 4. 验证 unstage

发送：

```text
把刚才 staged 的 src/app.py unstage，保留工作区修改，不要 commit。
```

预期 Agent 使用：

```text
git_unstage
```

Git 面板 Refresh 后：

```text
Staged = 0
Unstaged = 1
src/app.py
```

工作区文件内容仍然保留。

## 5. 验证显式 commit 双门槛

先发送：

```text
stage src/app.py，但不要 commit。
```

然后发送一个与 commit 无关的问题，例如：

```text
检查当前 diff 并告诉我改了什么。
```

预期：绝不能产生 commit。

接着明确发送：

```text
请 commit 当前已经 staged 的修改，commit message 使用：phase25 explicit commit
```

预期：

1. Agent 可以调用 `git_commit_prepare`；
2. 调用 `git_commit` 前出现 Approval；
3. 未点击 Allow 前不能 commit；
4. 点击 Allow once 后才创建 commit；
5. Git log 能看到：

```text
phase25 explicit commit
```

这一步验证：

```text
current user explicit intent
        +
runtime Approval
        =
允许 commit
```

仅有 Approval 不足以替代当前用户明确意图。

## 6. 验证 task worktree create

发送：

```text
为 Phase25 worktree 测试创建一个隔离 worktree，任务名 phase25-isolated，分支名 phase25/task-worktree，基于当前 HEAD。
```

预期：

- Agent 使用 `git_worktree_create`；
- 创建前需要 Approval；
- 创建目录位于 Local Coding Agent 数据目录的 `worktrees/` 下；
- 原始源码工程目录不会出现新的 worktree 子目录；
- 原工作区当前 branch 不改变。

Git 面板 Refresh 后，应多一个：

```text
phase25/task-worktree
Managed
Open
```

## 7. 验证一键打开 worktree

在 Git 面板对：

```text
phase25/task-worktree
```

点击：

```text
Open
```

预期：

- worktree 作为独立 Project 打开；
- 有自己的 Thread；
- 当前 branch 为 `phase25/task-worktree`；
- 原始 Project 仍保留在左侧 Projects，可以随时切回。

## 8. 验证 worktree 隔离

在 worktree Project 中发送：

```text
在 src/app.py 文件末尾添加注释：# PHASE25_WORKTREE_ONLY
```

然后切回原始 Project。

预期原始 Project 的：

```text
src/app.py
```

不包含：

```text
# PHASE25_WORKTREE_ONLY
```

说明工作目录隔离成立。

## 9. 验证 dirty worktree 不能删除

保持 worktree 内存在未提交修改。

切回原始 Project，发送：

```text
删除刚才 phase25/task-worktree 这个受管 worktree。
```

预期：

- 即使用户明确要求并通过 Approval；
- 删除仍应失败；
- 错误应为或明确表达：

```text
WORKTREE_DIRTY
Worktree has uncommitted changes and will not be removed.
```

工作目录必须仍然存在。

## 10. 验证 clean worktree 可删除

先在 worktree 中撤销测试注释，确保 Git 面板显示：

```text
Clean
```

切回原始 Project，再发送：

```text
删除 phase25/task-worktree 这个受管 worktree。
```

通过 Approval。

预期：

- worktree 删除成功；
- Git 面板 Refresh 后该 worktree 消失；
- 原始仓库内容和当前 branch 不受影响。

## 11. 验证 push 不会自行发生

固定测试工程没有配置 remote，所以本阶段不实际 push。

发送普通开发任务、stage、diff、worktree 等请求时：

- 不应出现 `git push`；
- 不应出现 publish Approval。

自动化测试已覆盖：

- 当前用户未明确说 push 时，shell `git push` 会在 PermissionPolicy 层直接拒绝；
- MCP Git publish 同样不能绕过显式意图要求。

## Phase 25 通过标准

1. Git 面板显示 current branch；
2. staged / unstaged / untracked 准确；
3. local branches 正常；
4. `git_stage` 正常；
5. `git_unstage` 保留工作区修改；
6. 非 commit 请求绝不自动 commit；
7. 显式 commit 仍需要 Approval；
8. task worktree 创建在源码树外；
9. worktree 可一键 Open 为独立 Project；
10. worktree 修改不污染原工作树；
11. dirty worktree 删除被拒绝；
12. clean managed worktree 可以删除；
13. 普通任务不会触发 push。
