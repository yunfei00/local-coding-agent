# v0.2 Phase 17 — Settings 人工验收

> 分支：`feature/v0.2`
>
> 自动化已经覆盖：设置持久化、参数校验、Provider 热切换协议、运行中禁止切换、API Key 不写 SQLite、不回传明文、Prompt Rules 后端和权限边界。本页只验证桌面交互与重启体验。

## 1. 启动当前分支

Windows PowerShell：

```powershell
git checkout feature/v0.2
git pull
.\scripts\dev\start.ps1
```

打开任意已有项目。

## 2. Settings 页面

点击右上角 `Settings`。

应看到 6 个页签：

- General
- Provider
- Agent
- Context
- Prompt Rules
- Safety

关闭 Settings 后，原来的项目、Thread 和聊天内容应保持不变。

## 3. Ollama 配置持久化

进入 `Provider`，保持 Provider 为 `Ollama`。

确认可以看到：

- Base URL
- Preferred model
- Context window
- Temperature

把 Temperature 暂时改成 `0.3`，点击 `Save settings`。

关闭 Settings 后重新打开，应仍是 `0.3`。

然后完全关闭 Local Coding Agent，再重新运行：

```powershell
.\scripts\dev\start.ps1
```

再次进入 Settings，Temperature 仍应为 `0.3`。

验证完成后可以改回 `0.2`。

## 4. Agent / Context

进入 `Agent`，应能看到：

- Max model steps
- Max tool calls
- Blocked repeats
- Failure limit
- Provider retry attempts

进入 `Context`，应能看到：

- Reserved output tokens

不需要修改这些值，只确认输入框正常、没有错位或溢出。

## 5. Prompt Rules

进入 `Prompt Rules`。

应看到：

- Global rules
- Project rules
- Thread rules

在 Global rules 输入：

```text
When summarizing code changes, always mention the changed file names.
```

保持 Enabled，点击 `Save rule`。

关闭 Settings，再打开，应能看到该内容仍然存在。

然后点击该规则的 `Reset`，确认内容被清除。

Project / Thread rules 只需确认当前已有项目和 Thread 时可以编辑；没有对应对象时应自动禁用。

## 6. Safety

进入 `Safety`。

把 Permission mode 从 `Workspace` 切到 `Read Only`。

关闭 Settings 后，聊天输入区底部的权限选择应同步显示 `Read Only`。

再切回 `Workspace`。

## 7. API Key 安全存储显示

进入 `Provider`，临时选择 `OpenAI-compatible`。

API Key 一栏应：

- 使用密码输入框；
- 已配置时不显示真实 Key；
- 页面只显示类似 `Stored with OS-protected encryption`、`Environment`、`Session only` 或 `Not configured`；
- 不应出现已保存 Key 的明文。

无需为了验收填写真实 API Key。

最后切回 `Ollama` 并保存。

## 验收结论

以上全部正常即可认为 Phase 17 人工验收通过。

特别关注：

1. Settings 关闭后聊天状态不丢。
2. 重启后非敏感配置仍存在。
3. Prompt Rules 能保存和 Reset。
4. Safety 与聊天页 Permission 同步。
5. API Key 不出现明文。
