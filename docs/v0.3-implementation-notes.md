# v0.3 本轮实现与验收说明

## Phase 26

- 多步骤列表（至少三步）和较长的复杂开发请求可自动创建计划，短任务不强制计划。
- 仍支持用户显式创建、编辑、排序和调整状态；执行期间禁止修改计划。
- 每次工具执行先持久化 running，再写入 succeeded / failed、退出码和变更路径；不保存参数、输出或隐藏推理。
- 步骤完成关联真实工具调用 ID，手写备注、伪造 ID、其他步骤的 ID、失败的命令均不能作为完成证据。
- 中间实现步骤可以先完成，再由后续验证步骤运行测试与检查 Diff。最终完成仍受全局验证门槛约束。
- 失败测试阻塞当前步骤，不会因后续工具成功而跳过。用户必须先处理阻塞状态。
- Stop 后保存检查点，重启恢复不会重置已完成步骤；未完成且执行过的步骤需检查工作区并点击 Continue plan，服务端确认后才能恢复。
- 每个计划最多保存最近 50 个检查点，步骤证据单独保留。
- `tests/test_v03_runtime.py` 在固定计算器工程的临时副本中执行实际读取、Patch、unittest、Git Diff，确定性 Provider 只决定工具请求，不伪造工具结果。

自然语言 verification 仍只能要求成功命令证据，不能自动证明任意业务语义。测试失败基线必须记录为失败；如计划包含“确认失败”，该步骤会阻塞，需用户检查后调整，不能将失败测试自动标记为成功。

## Phase 27

- 运行循环计数模型步骤、实际重试、工具调用/失败/耗时；成功完成事件附带 execution_summary。
- 所有终止路径通过正式 `turn.metrics` 事件发出有限大小的统计，包含 Provider、Model、上下文 Token 估算与来源。
- history 和 tool_output 按最终选入预算的消息计算；pinned_file、mentioned_file、repo_map 等来源由 ContextBudgetManager 提供。
- 桌面每轮展示可展开的紧凑执行摘要，并可复制白名单脱敏轨迹。
- Diagnostics 增加 Agent 运行状态、Worktree 数量/状态和 Repository Map 文件数/修订号；保留 MCP 状态。
- 只保留最近一轮诊断摘要，不在 SQLite 累积模型思考或原始轨迹。API Key、MCP 秘密和敏感环境变量参与精确脱敏。

## Windows 与环境

- uv.lock 与 npm lock 共同固定依赖；npm 的 Agent 命令改用 uv run。
- Windows Shell 使用 kill-on-close Job Object 约束后代进程，取消、超时、正常退出均释放进程树与管道。
- 本地验收自动定位 uv 与 npm.cmd，保存编号错误、完整本地日志、阶段退出码和耗时。
- 打包脚本对原生命令检查退出码，清理仅允许 build 与 desktop/release 中的路径；安装冒烟使用唯一目录。

## UI

- 保持项目稳定排序与独立展开，将展开状态、浅色/深色主题持久化。
- 非当前项目的会话可以直接打开和改名。
- Markdown、代码、表格与复制按钮；HTML 不执行，危险链接协议由渲染库过滤。
- 工具结束后默认折叠，运行期间保留实时反馈；用户消息与 Agent 输出保持清晰层级。
- Context / Git / Plan / Diagnostics 使用工作区右侧独立列，互斥切换，可关闭，不覆盖聊天输入。
- 发送失败保留草稿并移除失败的乐观消息；防止重复提交。

设计参考：[官方桌面应用文档](https://learn.chatgpt.com/docs/app)。三栏布局、间距、主题与组件细节是本项目自己的实现，不使用官方品牌资源。
