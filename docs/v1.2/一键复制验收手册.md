# Local Coding Agent v1.2 一键复制验收手册（Windows）

> 测试分支：`feature/v1.2.0-agent-skills`。这是尚未正式发布的开发分支，不要用 v1.1.0 正式版测试 v1.2 新能力。
>
> **统一规则**：每次只复制一个「任务指令」代码块到 Local Coding Agent 对话框；任务结束后只需要复制对应的「反馈行」给 ChatGPT。**不允许模型声称未实际执行的操作已经通过。**

## 0. 测试准备

1. 使用包含 `feature/v1.2.0-agent-skills` 的 Windows 测试版本；确认 Agent 已连接本地/在线模型，且工程能正常打开。
2. 新建**空白**工程：`D:\LCA-v12-Acceptance`。以下所有产物必须放在这个工程中，不得操作其他目录。
3. 运行时可以授权工作区文件创建；涉及浏览器点击、外部网站、Office COM 或其他敏感动作时遵守界面权限提示。不要直接关闭安全保护。
4. 如需验证 COM/PDF/UIA，请在 Windows 安装 Microsoft Excel、Word、PowerPoint。没有安装时反馈「环境缺失」，不要当作通过。
5. **禁止使用真实账号、客户数据、生产网站、公司保密资料**。浏览器测试优先使用测试页面或公开无登录页面。

## 1. Office 三件套：新建文件

**任务指令（完整复制）：**

```text
请在当前工程中自主完成一套 2026 年第三季度销售分析交付物，并实际调用可用工具完成验证。所有数据使用虚构样例，不能修改工程外文件。

A. 创建 sales_2026_q3.xlsx，至少包含「销售明细」「月度汇总」两个工作表；明细至少 12 行，包含月份、产品、销量、单价、销售额，销售额使用 Excel 公式。月度汇总的合计值必须与明细一致。尽可能添加柱状图；如果当前 Office 工具不支持图表，请明确标记为「不支持」，不能伪造成功。
B. 创建 sales_report.docx，包含标题、摘要、月度分析、至少一张表格、问题与建议；数字必须与 Excel 一致。
C. 创建 sales_presentation.pptx，至少 6 页，包含封面、总览、月度趋势、产品分析、问题、建议。
D. 使用 Office 文件读取/结构检查工具验证以上文件，能检查的内容逐项检查，生成 acceptance-office-01.md 中文报告。不要把结构检查等同于视觉排版验证。
E. 任务结束只输出一行，严格格式：
OFFICE01 | Excel=PASS/FAIL | 公式=PASS/FAIL | 图表=PASS/FAIL/UNSUPPORTED | Word=PASS/FAIL | PPT=PASS/FAIL | 报告=PASS/FAIL | 原因=一句话
所有 PASS 必须有真实文件或工具结果支持。不得编造文件。
```

**人工只需确认**：工程目录出现 3 个 Office 文件和 1 个 Markdown 报告。若缺文件，直接反馈失败。

## 2. Office 已有文件修改

**任务指令：**

```text
请基于当前工程已有的 sales_2026_q3.xlsx、sales_report.docx、sales_presentation.pptx 继续修改，不得重新创建无关文件，也不得覆盖工程外文件。

1. Excel 增加 10 月销售数据并更新相应公式与汇总；如支持图表同步更新。
2. Word 新增「第四季度预测」章节，并保留原有章节与表格。
3. PPT 增加一页「第四季度预测」，保留原有幻灯片。
4. 修改前后分别读取并核对原内容与新增内容，生成 acceptance-office-02.md。
5. 结束只输出：
OFFICE02 | Excel修改=PASS/FAIL | Word修改=PASS/FAIL | PPT修改=PASS/FAIL | 原内容保留=PASS/FAIL | 报告=PASS/FAIL | 原因=一句话
```

## 3. Windows 原生 Office：COM、PDF、UIA

**任务指令：**

```text
请先检查 Windows 是否安装 Microsoft Excel、Word、PowerPoint。若没有，明确返回 ENV_MISSING，不得伪造测试。

在当前工程内：
1. 检测 Office COM 接口可用性。
2. 用 COM 修改已有 Office 文件的副本，不覆盖原文件；分别报告支持与否。
3. 尝试将 Word 文件通过本机 Office 导出为 PDF，实际检查 PDF 是否存在且可打开。
4. 打开至少一个 Office 窗口并检查 UIA 窗口发现能力。UIA 窗口发现不等于完整桌面点击控制。
5. 生成 acceptance-office-03.md，注明真实执行与不支持的功能。
6. 结束只输出：
OFFICE03 | 环境=READY/ENV_MISSING | COM=PASS/FAIL/UNSUPPORTED | PDF=PASS/FAIL/UNSUPPORTED | UIA=PASS/FAIL/UNSUPPORTED | 报告=PASS/FAIL | 原因=一句话
```

## 4. Skills：发现、读取、安装、备份、回滚

**任务指令：**

```text
请测试当前 Local Coding Agent 的 Skills 管理功能。仅在当前测试工程内创建一个无害的测试 Skill，名称 demo-acceptance，描述为「读取工程文件并生成摘要」；内容只包含说明文字，不执行外部脚本，不连接真实账号。

1. 检查 Skills 列表/搜索与 SKILL.md 内容读取。
2. 测试测试 Skill 的安装或注册、启用、查看详情（按当前实现支持范围）。
3. 若有备份、更新、回滚、审计记录功能，请实际验证一次；不支持则标记 UNSUPPORTED。
4. 不修改其他 Skills、不访问工程外文件。生成 acceptance-skills.md。
5. 结束只输出：
SKILLS | 列表=PASS/FAIL | 读取=PASS/FAIL | 安装=PASS/FAIL/UNSUPPORTED | 备份回滚=PASS/FAIL/UNSUPPORTED | 审计=PASS/FAIL/UNSUPPORTED | 原因=一句话
```

## 5. 浏览器自动化：真实页面交互

**任务指令：**

```text
请使用 Local Coding Agent 自带的 browser_session 浏览器工具，不要用普通 HTTP 请求冒充浏览器交互。

1. 检查 Playwright/Chromium 是否可用；若缺失则报告 ENV_MISSING。
2. 仅使用公开、无需登录的测试页面（例如 https://example.com）打开会话。
3. 实际执行页面快照、读取标题和正文、截图保存到当前工程、提取表格（若页面无表格，标记 NO_TABLE 而不是失败）。
4. 使用 workflow 的 assert_text 和 assert_url 验证页面内容和 URL。
5. 关闭浏览器会话；记录每步真实工具结果。不要登录账号，不要提交外部表单。
6. 生成 acceptance-browser.md。
7. 结束只输出：
BROWSER | 环境=READY/ENV_MISSING | 打开=PASS/FAIL | 快照=PASS/FAIL | 截图=PASS/FAIL | 断言=PASS/FAIL | 关闭=PASS/FAIL | 原因=一句话
```

> 备注：如果模型不能主动调用 browser_session，可在「设置 → 浏览器自动化」界面手工输入 `https://example.com`，测试打开、快照、截图、断言、关闭，并在反馈中说明「UI 手动测试」。

## 6. 自动验收与失败修复

**任务指令：**

```text
请使用当前工程中的 Office 三件套验证自动验收功能，不要使用虚构结果。

1. 调用 deliverable_verify 检查 Excel 工作表名称和指定单元格、Word 关键文本、PPT 关键文本。
2. 人为设置一条与现有 Excel 数据不一致的预期单元格值，确认第一次验证 FAIL。
3. 在获得所需权限后，显式开启 repair，最多 2 轮，仅修复该 Excel 测试单元格；不得修改其他工作表、Word、PPT。
4. 重新运行相同断言，确认结果 PASS，保存中文报告 acceptance-repair.md。
5. 如果工具无法修复，请记录原始错误，不得直接宣称通过。
6. 结束只输出：
REPAIR | 初次失败=PASS/FAIL | 自动修复=PASS/FAIL | 二次验证=PASS/FAIL | 非目标文件未改动=PASS/FAIL | 报告=PASS/FAIL | 原因=一句话
```

## 8. CI 与最终判定

- GitHub PR #39: https://github.com/yunfei00/local-coding-agent/pull/39
- Actions: https://github.com/yunfei00/local-coding-agent/actions
- 只有最新提交的 **Core checks Windows/Ubuntu + v1.2 Skills/Office Windows/Ubuntu** 全部绿色，才算 CI 通过。
- **CI 通过不代表 Windows 真机 Office/记事本、真实模型、安装包的全部功能通过**。真机部分以本手册实际执行结果为准。
- 任一测试任务失败时保留工程文件、验收报告与简短错误，不要直接删除证据。

## 9. 最简洁反馈方式

正常只需要把 Agent 的最后一行复制给 ChatGPT，例如：

```text
OFFICE01 | Excel=PASS | 公式=PASS | 图表=UNSUPPORTED | Word=PASS | PPT=PASS | 报告=PASS | 原因=当前工具未实现图表
```

如果 Agent 卡住、崩溃或无法产生报告，只回复：

```text
OFFICE01 | BLOCKED | 步骤=创建Excel | 错误=原始错误消息（最多200字）
```

**请按 OFFICE01 → OFFICE02 → OFFICE03 → SKILLS → BROWSER → REPAIR → DESKTOP 的顺序执行。** 如不具备 Microsoft Office，可先跳过 OFFICE03 并标记 ENV_MISSING。无需截图整个桌面或粘贴冗长日志，只有无法定位时再提供对应的失败日志片段。
