## 追加定位记录

- 第二批完整验收为 19/21。引用文件被写成源文件正文，Git 一轮因 Windows PowerShell 重定向产生二进制差异。通过原始用户文字抽取新文本文件的字面文件名约束并检查实际文件，不自动覆写。对已明确观察到的 Git 文本差异允许按原权限修复，早先拒绝的命令仍不可重试。随后文件引用与 Git 各自独立复验 3/3。
- Windows 前台夹具最初使用 uv 虚拟环境启动器，记录的进程 PID 和实际 Tk 窗口 PID 不一致。改为启动底层解释器，由产品桌面工具只激活测试自有窗口，再由 Gemma 请求切换到记事本。两批各 3/3，均记录不同前后 PID、真实输入和独立保存读回。
- 隔离命令首次复验发现，相对路径子进程无法在空目录找到源码，模型因而回到交付目录运行。小项目现在只同步经过读取边界检查的源码副本，保留隔离数据。负例可声明精确预期退出码，原退出码和独立验收不变。针对性 CLI 曾达到 3/3。
- 第三批完整验收的两轮 CLI 出现相同新签名：真实测试文件第一次已移入恢复目录，随后命令重新创建文件，第二次删除被旧路径指纹误判成重放。仅对任务开始时不存在的路径，结合当前文件身份区分这两个真实文件。原有路径和不可确定基线继续使用原保护。权限和恢复目录行为保留。
- 一次 Git 连接等待没有收到终态。后端现为未预期异常发送脱敏失败事件并保留错误类型和代码位置，避免客户端误等到外层超时。

## Windows CI 路径兼容复验

首次 Windows CI 在引用检查测试中触发短路径别名。根目录经项目读取策略规范化，而被检查文件仍以调用者传入的目录拼接，导致边界检查拒绝了实际同一目录的文件。现统一从策略解析后的根目录取文件。原断言继续保留，本地定向回归通过，受影响的真实 Gemma 文件用例再次 3/3。21/21 的完整批次使用的工作区根目录已经规范化，其余真实验收证据继续有效。双平台最终状态见最新 PR 检查。
