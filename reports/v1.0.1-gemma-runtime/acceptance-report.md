# Gemma 自主开发复测

## 基线与参数来源

基线为 PR #34 的 `de8ce40`。Windows 上的真实验收只使用既有局域网 Ollama 的 `gemma4:31b`，数据目录和工程逐轮隔离。模型设置覆盖只写入测试数据目录。

旧验收器通过环境变量写入 8,192 上下文、18 步和 1,024 内部输出预留，桌面路径又写入同样的显式模型配置。旧生产聊天路径把内部输出预留补写到 Provider 的 `max_output_tokens`，Ollama 将其发送为 `num_predict`。模型目录和旧界面也为未配置上限的 Ollama 模型填过 1,024。三个值的来源独立。

现在 Ollama 模型可以把上限留空，客户端省略 `num_predict`。显式正整数仍会传递，拒绝负数等特殊值。内部上下文和累计预算继续保留输出预留，API 模型仍有明确输出上限和预算保护。已保存的显式值继续生效。验收器默认读取所选模型配置，覆盖值随结果记录。模型步数沿用 Runtime 设置，长任务还受累计模型调用、时间和重复操作保护。

## 服务器实测

Ollama 0.21.0。主机有 251 GiB RAM，探测前可用约 177 GiB，两张显卡各约 32,607 MiB。32K 加载后，`ollama ps` 显示实际分配 32,768、100% GPU，模型和上下文占用约 27 GB，承载卡剩余约 6 GiB。此次使用 32K，未测试 64K。模型元数据标示的 262,144 是模型上限，实际已验证的服务分配为 32,768。

原生 `/api/chat` 使用 32,768、同一长生成提示、temperature=0、think=false。

## 后续定位与复测

- CLI 原三轮均生成可执行项目并完成调用，没有因输出长度终止。独立断言仍因交付目录残留样例数据失败。运行时对命令新生成、尚未审查的数据文件提供一次有界核对，用户已有数据和已知交付物不自动移除。
- Git 首轮完成，第二轮遗漏基线文件，第三轮 diff 中新增行多一个前导空格。仍需提高稳定性。
- 桌面诊断还发现两处验收器问题。输入审批事件把正文脱敏，旧验收器无法核对原文本；修复后用当前认证会话和目标窗口绑定的 HMAC 核对精确内容。文本录入后标题出现 `*`，旧窗口所有权检查误判为已经退出并拒绝保存。现在仍核对原 HWND、PID 和精确文件名，同时接受未保存标记。最小化仅用于测试窗口已在前台时建立真实的切换起点。单独的测试窗口清理不计分。
- 编辑框点击在 UIA 通过精确控件聚焦，重新核验前台和实际键盘焦点。普通按钮继续使用 InvokePattern。原生记事本对照实际完成点击、输入、Ctrl+S 和读回。
- 空白待办 CLI 首次复测通过，运行时有持久化计划和独立验证证据。扫描器第一次被共享 pytest 临时目录 ACL 阻断，后续每轮使用独立临时目录。补测明确写出原断言要求的 `path` 列，断言不变，补测通过。
- 计算器第一次在真实验证通过后仍保留旧 `PATCH_NOT_FOUND`。后端现在只在同路径确实被后续成功写入时结清这类失败，独立测试仍执行。无关路径写入和权限拒绝不会结清。空白工程补测通过 pytest、窗口可见性、按键、四则运算和除零断言。

## 最终判定

| 用例 | 上轮 | 本轮对应验收 |
| --- | ---: | --- |
| CLI | 0/3 | 0/3。两次追加复测仍失败，一次清理后又生成样例数据，一次重复变更被拦截后达到工具失败上限。 |
| Git | 0/3 | 1/3。保留另外两轮的漏追踪及空白字符错误。 |
| 桌面 | 0/3 | 1/3。三轮均真正输入并保存，读回一致。另两轮因没有独立记录到前台从其他进程切换，原断言仍判 FAIL。 |
| 三个空白工程 | 0/3 | 3/3。扫描器和计算器使用修复后的追加复测。 |

针对性九轮按相同断言由 0/9 提升到 2/9。额外两轮桌面焦点探测一轮通过、一轮缺少切换证据，两轮均真实保存并读回。初期阻断、失败和追加运行均保留在机器可读结果中。由于 CLI 与 Git 尚未稳定，本轮完整 21 轮为 **NOT_RUN**，没有可比的新 21 轮总分。此前完整基线为 9/21（42.9%）。

固定生成上限和失效审批、旧补丁误阻断已修复。CLI 交付残留测试数据、Git 最终状态未稳定满足断言以及前台切换证据波动，仍阻断自主验收。现有正式安装和正式数据保持原样。分支继续用于审查，Windows 和 Ubuntu 最终状态以 PR #34 检查为准。
